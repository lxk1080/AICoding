# 《打砖块》开发任务清单

## 使用说明

本清单根据《[概要设计](gaiyao.md)》与《[详细设计](xiangxi.md)》拆分，按建议开发顺序排列。首版采用 HTML5、CSS3、Canvas 2D API 和原生 JavaScript（ES Modules），不引入第三方依赖。

按键以详细设计为准：左/右方向键或 A/D 移动，Enter 发球，Space 或 Escape 暂停/继续。

## 阶段 1：项目骨架与静态界面

- [ ] 创建入口 HTML、主样式文件和 JavaScript 模块目录。
- [ ] 在 HTML 中建立游戏画布、HUD 和通用遮罩层容器。
- [ ] 设置 Canvas 逻辑尺寸为 `800 × 600`，并通过 CSS 适配页面容器。
- [ ] 实现 HUD 的关卡、分数、生命显示区域。
- [ ] 实现开始、暂停、关卡结算、游戏结束、通关五类弹层内容与按钮。
- [ ] 建立集中管理的常量模块：画布、挡板、小球、砖块、物理与道具数值。
- [ ] 验收：打开页面能看到游戏区域和开始界面；页面不依赖后端或第三方包。

## 阶段 2：游戏状态与主循环

- [ ] 定义 `START`、`READY`、`PLAYING`、`PAUSED`、`LEVEL_CLEAR`、`GAME_OVER`、`VICTORY` 状态。
- [ ] 建立统一的 `GameState`：关卡索引、分数、生命、挡板、小球数组、砖块数组、道具数组和效果集合。
- [ ] 使用 `requestAnimationFrame` 实现主循环。
- [ ] 计算 `deltaTime` 并限制最大值为 `0.05s`，防止恢复页面焦点后物体跳跃。
- [ ] 实现状态机转换与弹层显示：开始新游戏、准备发球、暂停恢复、失球、清关和最终通关。
- [ ] 实现 HUD 随状态同步更新。
- [ ] 验收：开始、暂停、继续、游戏结束和重新开始的状态转换正确，暂停期间不更新游戏时间。

## 阶段 3：输入系统与挡板

- [ ] 建立语义化 `InputState`：`left`、`right`、`launch`、`pause`。
- [ ] 绑定 `ArrowLeft`/`KeyA` 为左移，`ArrowRight`/`KeyD` 为右移，并阻止方向键滚动页面。
- [ ] 绑定 Enter 为发球；只在 `READY` 状态首次按下时生效。
- [ ] 绑定 Space 和 Escape 为暂停/继续；只在 `READY`、`PLAYING` 状态生效。
- [ ] 页面失焦时清除已按下的按键状态并自动暂停。
- [ ] 实现挡板实体的坐标、尺寸、速度与基础宽度字段。
- [ ] 根据左右输入和 `deltaTime` 更新挡板位置，并限制在画布边界内。
- [ ] 验收：挡板移动平滑、不出界；双向同时按下时静止；失焦后不会出现按键卡住。

## 阶段 4：小球、发球与基础反弹

- [ ] 实现小球实体：圆心坐标、半径、速度和发射状态。
- [ ] 在 `READY` 状态让小球附着于挡板中心上方，并随挡板移动。
- [ ] Enter 发球时初始化小球向上运动速度，切换至 `PLAYING`。
- [ ] 实现小球与左右、上边界碰撞后的坐标修正与速度反转。
- [ ] 实现小球越过底部边界后的离场标记与移除。
- [ ] 实现挡板碰撞：仅处理向下运动的小球，防止从下方误反弹。
- [ ] 依据命中点相对挡板中心的偏移计算最大 60° 的反弹角度。
- [ ] 保证反弹后的 y 方向向上，并限制最小垂直速度，避免小球长时间水平移动。
- [ ] 验收：小球在墙壁和挡板上稳定反弹；接近挡板两端时反弹方向明显更倾斜。

## 阶段 5：关卡与砖块系统

- [ ] 定义二维数组关卡格式，以及 `0` 空位、`1` 普通砖、`2` 坚固砖、`3` 金属砖、`4` 道具砖的映射。
- [ ] 配置 3 个由易到难的关卡：普通砖入门、坚固砖与缺口、金属砖障碍。
- [ ] 实现根据布局数据生成砖块实例的函数，并统一计算坐标、尺寸和间隔。
- [ ] 实现普通砖、坚固砖、金属砖、道具砖的字段及不同绘制样式。
- [ ] 实现圆形小球与矩形砖块的最近点碰撞判定。
- [ ] 实现碰撞主轴判断、速度反转和小球推出重叠区域。
- [ ] 普通砖与道具砖命中一次销毁；坚固砖命中两次销毁；金属砖只反弹。
- [ ] 保证同一小球在同一帧对同一砖块最多造成一次伤害。
- [ ] 为高速小球增加子步更新或等效防穿透处理，子步上限建议为 8。
- [ ] 验收：四类砖块行为和碰撞反馈符合设计；金属砖不影响清关判定；高速运动不应经常穿过砖块。

## 阶段 6：计分、生命与关卡流程

- [ ] 实现普通砖、道具砖 100 分，坚固砖累计 200 分的得分规则。
- [ ] 实现小球数组为空时扣除一次生命的规则。
- [ ] 失球且生命大于 0 时保留当前砖块、分数、生命，进入 `READY` 重新发球。
- [ ] 生命归零时进入 `GAME_OVER`，展示最终分数和重新开始入口。
- [ ] 检查所有可破坏砖块是否清除；清关时增加 `剩余生命 × 500` 分。
- [ ] 实现关卡结算和下一关加载；最后一关完成后进入 `VICTORY`。
- [ ] 同帧发生清关与最后一球离场时，优先按清关处理。
- [ ] 验收：分数、生命和关卡信息实时正确；完整走通三关并能正确结算。

## 阶段 7：道具系统

- [ ] 实现道具砖销毁时按 20% 概率生成掉落物。
- [ ] 实现掉落物的类型、位置、尺寸和向下移动；越过底部后移除。
- [ ] 实现掉落物与挡板的矩形相交检测及接取逻辑。
- [ ] 实现“扩展”：挡板宽度暂时变为基础宽度的约 1.5 倍，持续 15 秒。
- [ ] 实现“多球”：基于现存球新增两球，直到各球离场。
- [ ] 实现“减速”：小球速度暂时降低，持续 10 秒，避免重复叠乘。
- [ ] 实现“穿透”：命中砖块造成伤害但不反弹，持续 8 秒。
- [ ] 实现“额外生命”：生命加一且不超过 5；达上限时转为固定加分。
- [ ] 使用“效果类型 → 到期时间/参数”管理临时效果；重复接取同类效果时刷新时长。
- [ ] 在失球和切换关卡时清除临时效果与掉落物，恢复基础挡板属性。
- [ ] 验收：五种道具可正常掉落、接取、生效和结束；多球仅在最后一球离场时扣生命。

## 阶段 8：渲染、反馈与可用性

- [ ] 实现 Canvas 每帧清屏及背景、边框、砖块、道具、挡板、小球、提示文本的分层绘制。
- [ ] 为坚固砖提供耐久受损的可视化变化。
- [ ] 在砖块命中、小球碰撞和道具接取时添加轻量视觉反馈（闪烁、缩放或粒子）。
- [ ] 在 `READY` 状态显示“按 Enter 发球”的提示。
- [ ] 确保按钮可鼠标点击，关键动作仍可使用键盘完成。
- [ ] 确保生命、道具类型等状态不只通过颜色表达。
- [ ] 验收：游戏信息清晰可读，状态变化可见，所有关键流程均有明确提示。

## 阶段 9：可选功能

- [ ] 使用 `localStorage` 保存并读取最高分、静音偏好和已解锁关卡；不可用时无提示降级。
- [ ] 加入静音开关与不同的墙壁、挡板、砖块、道具、失球和通关音效。
- [ ] 实现音频加载/播放失败时静默降级，不影响游戏。
- [ ] 预留鼠标、触摸控制及响应式坐标换算，作为移动端扩展基础。

## 阶段 10：测试与发布前检查

- [ ] 在 Chrome、Edge、Firefox、Safari 的现代版本中验证可启动与可游玩。
- [ ] 检查不同刷新率下挡板和小球速度是否近似一致。
- [ ] 覆盖墙壁、挡板边缘、砖块边角、连续命中和高速小球碰撞。
- [ ] 覆盖暂停、失焦恢复、失球、清关、游戏结束、最终通关和重新开始。
- [ ] 覆盖五种道具、效果到期、重复接取、生命上限及多球最后离场。
- [ ] 检查重新开始、换关和失球后旧小球、掉落物、效果是否被清理。
- [ ] 检查无音频和 `localStorage` 不可用时核心玩法是否正常。
- [ ] 手工完成一次完整三关流程，确认首版验收项均通过。

## 完成定义

当阶段 1 至阶段 8 的任务全部勾选，且阶段 10 的核心测试通过时，首版《打砖块》即可交付。阶段 9 为非阻塞的可选增强项。
