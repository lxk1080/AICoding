# 《打砖块》详细设计

## 1. 文档目的与约定

本文档给出首版《打砖块》的实现级设计，配合《[概要设计](gaiyao.md)》和《[游戏设计文档](game-design.md)》使用。描述的是模块接口、运行顺序、数据模型与算法约束，不包含可直接运行的代码。

逻辑坐标使用像素；速度单位为“像素/秒”；时间单位为“秒”。所有可变运行数据只由 `Game` 统一持有和调度。

## 2. 常量设计

| 分组 | 建议常量 | 建议值/约束 |
| --- | --- | --- |
| 画布 | `CANVAS_WIDTH`、`CANVAS_HEIGHT` | `800`、`600` |
| 挡板 | 初始宽/高、速度、底部边距 | `120 / 16 / 520 / 24` 左右；以实际手感微调 |
| 小球 | 半径、初始速度、最大速度 | 半径约 `8`；初速约 `320 px/s` |
| 物理 | `MAX_DELTA_TIME`、`MAX_BOUNCE_ANGLE` | 最大帧间隔 `0.05s`；最大反弹角 `60°` |
| 砖块 | 列数、宽高、间隔、顶部边距 | 以 10 列布局为基准 |
| 规则 | 初始生命、生命上限、掉落概率 | `3`、`5`、`0.2` |
| 效果 | 扩展/减速/穿透时长 | `15s / 10s / 8s` |

数值应集中在常量模块，禁止在碰撞、绘制或 UI 中散落同一规则的硬编码值。

## 3. 数据模型

### 3.1 游戏运行状态

```text
GameState
  status: START | READY | PLAYING | PAUSED | LEVEL_CLEAR | GAME_OVER | VICTORY
  levelIndex: number
  score: number
  lives: number
  paddle: Paddle
  balls: Ball[]
  bricks: Brick[]
  powerUps: PowerUp[]
  effects: Map<PowerUpType, Effect>
  pressedKeys: InputState
  lastFrameTime: number
```

`balls` 采用数组而不是单一小球字段，为多球能力预留。清关检查只统计 `breakable === true` 且未被摧毁的砖块。

### 3.2 实体字段

| 实体 | 字段 | 说明 |
| --- | --- | --- |
| `Paddle` | `x, y, width, height, speed, baseWidth` | `x/y` 为左上角；`baseWidth` 用于效果结束后恢复。 |
| `Ball` | `x, y, radius, vx, vy, launched` | `x/y` 为圆心；`vx/vy` 为速度。 |
| `Brick` | `id, x, y, width, height, type, hp, score, breakable, destroyed` | `type` 决定耐久、颜色和是否掉落道具。 |
| `PowerUp` | `id, type, x, y, width, height, fallSpeed` | `x/y` 为左上角；落至底部后移除。 |
| `Effect` | `type, expiresAt, value` | 短时效果的到期时间与强度参数。 |

## 4. 关卡配置

关卡由纯数据定义，建议采用二维格子矩阵。每项映射如下：

| 值 | 砖块类型 |
| --- | --- |
| `0` | 空位 |
| `1` | 普通砖 |
| `2` | 坚固砖 |
| `3` | 金属砖 |
| `4` | 道具砖 |

关卡对象至少包含 `name`、`speedMultiplier` 和 `layout`。加载函数读取布局，根据行列索引计算砖块位置：

```text
x = 左边距 + 列索引 × (砖宽 + 横向间隔)
y = 顶部边距 + 行索引 × (砖高 + 纵向间隔)
```

金属砖同样生成并参与碰撞，但不计入目标砖块数。

## 5. 初始化与状态迁移

### 5.1 初始化

1. 创建 Canvas、HUD 与各类弹层的 DOM 引用。
2. 初始化 `Input`，注册键盘按下和松开事件。
3. 读取可选的本地设置（最高分、静音）。
4. 创建 `GameState`，状态设为 `START`。
5. 启动 `requestAnimationFrame` 循环；开始界面仅绘制静态背景。

### 5.2 开始新游戏

1. 设定 `score = 0`、`lives = 3`、`levelIndex = 0`。
2. 清空效果、掉落物与旧小球。
3. 加载第一关砖块，创建默认挡板。
4. 调用“准备发球”，状态切换为 `READY`。

### 5.3 准备发球

1. 清空场上掉落物与临时效果，恢复挡板默认宽度。
2. 若为失球后重发，仅保留现有关卡砖块、分数和生命。
3. 创建一个未发射小球，并使其圆心位于挡板水平中心上方一个半径距离处。
4. 状态设为 `READY`；小球每帧随挡板移动。

### 5.4 状态迁移限制

- 仅 `READY` 接受发球指令。
- 仅 `READY` 与 `PLAYING` 可暂停。
- `PAUSED` 恢复前的状态，以避免暂停后错误地切换到其他状态。
- `LEVEL_CLEAR` 点击下一关后增加 `levelIndex` 并重新加载关卡；最后一关则进入 `VICTORY`。

## 6. 帧更新顺序

当状态为 `PLAYING` 时，每帧按固定顺序更新：

1. 计算并截断 `deltaTime`，避免长时间切后台后物体跳跃。
2. 根据键盘状态更新挡板位置，并限制在画布内。
3. 清理已过期效果，恢复受影响的基础属性。
4. 对每个小球执行移动、边界碰撞、挡板碰撞、砖块碰撞。
5. 根据被摧毁的砖块更新分数，并在道具砖被击碎时按概率创建掉落物。
6. 更新掉落物位置，检测其与挡板的接取。
7. 移除离开底部的小球；若数组为空则执行失球流程。
8. 检查剩余可破坏砖块数，若为零执行清关流程。
9. 更新 HUD；最后调用渲染器绘制画面。

若同一帧既可能清关又可能失去最后一个球，优先判定清关；这是玩家更易理解、且更有利的规则。

## 7. 输入设计

`InputState` 至少维护 `left`、`right`、`launch`、`pause` 四个语义状态，而不是在业务逻辑中直接判断具体按键。

| 原始输入 | 语义状态 | 注意事项 |
| --- | --- | --- |
| `ArrowLeft`、`KeyA` | `left` | 阻止浏览器默认滚动。 |
| `ArrowRight`、`KeyD` | `right` | 阻止浏览器默认滚动。 |
| `Enter` | `launch` | 仅在按键首次按下时触发一次。 |
| `Space`、`Escape` | `pause` | 仅在按键首次按下时切换一次。 |

左右键同时按下时挡板静止。页面失焦时清空所有按键状态并自动暂停，避免恢复焦点后出现“按键卡住”。

## 8. 对象更新细节

### 8.1 挡板

移动方向由 `right - left` 得出，位置更新公式为：

```text
paddle.x += direction × paddle.speed × deltaTime
paddle.x = clamp(paddle.x, 0, canvasWidth - paddle.width)
```

处于 `READY` 的小球应在挡板位置变化后同步更新 x 坐标。

### 8.2 小球与墙壁

小球位置更新：

```text
ball.x += ball.vx × deltaTime
ball.y += ball.vy × deltaTime
```

与左、右、上边界相交时，分别修正坐标到边界内，再翻转相应速度分量。底边界不反弹；小球完全越过底部即标记为离场。

### 8.3 挡板反弹

仅处理正在向下运动、且圆形边界与挡板矩形相交的小球。命中后：

1. 将球移至挡板上方，消除重叠。
2. 计算 `offset = (ball.x - paddleCenterX) / (paddle.width / 2)`，再限制至 `[-1, 1]`。
3. `angle = offset × MAX_BOUNCE_ANGLE`。
4. 以当前速度大小 `speed` 重设速度：水平分量随 `sin(angle)` 变化，垂直分量取向上的负值。
5. 垂直速度绝对值低于最小阈值时提升至阈值，并按总速度重新归一化。

该方法使接近挡板边缘的击球更倾斜，中心击球更垂直。

### 8.4 小球与砖块

对每个未销毁砖块进行圆-矩形检测：

1. 将球心 x、y 分别夹取到砖块矩形范围，得到矩形最近点。
2. 计算球心到最近点的平方距离；小于等于半径平方即发生碰撞。
3. 判断撞击主轴：比较球心相对砖块中心的归一化水平/垂直偏移，或使用最小穿透距离。
4. 若未获得穿透效果，沿主轴翻转 `vx` 或 `vy`，并把球推出砖块。
5. 对该砖块执行一次伤害；同一球同一帧对同一砖块只能伤害一次。

金属砖只执行反弹。普通砖与道具砖命中一次即销毁；坚固砖第一次命中减少耐久并改变绘制样式，耐久为零时才销毁和计分。

为减少高速穿透，可基于当前球速将本帧拆为 `ceil(位移 / 球半径)` 个子步更新，子步数量设置合理上限（如 8）。

## 9. 道具设计

### 9.1 掉落与接取

道具砖销毁时，以 20% 概率从预设道具池随机选取一种。掉落物从砖块中心生成，以固定速度向下移动；其矩形与挡板矩形相交即被接取。越过画布底部后移除。

### 9.2 效果处理

| 类型 | 应用方式 | 结束方式 |
| --- | --- | --- |
| 扩展 | 将挡板宽度设为基础宽度的约 1.5 倍，并保持中心位置不突变 | 到期恢复基础宽度 |
| 多球 | 以当前球为基础生成两枚方向略有偏移的新球 | 各小球离场后自然消失 |
| 减速 | 将所有现存球速度乘以约 0.75，并记录恢复参数 | 到期按基准速度比例恢复；不重复叠乘 |
| 穿透 | 使所有球的砖块碰撞跳过速度反转 | 到期移除标记 |
| 额外生命 | `lives = min(lives + 1, 5)` | 达上限时改加固定分数 |

相同定时道具重复接取时只刷新到期时间，不重复叠加数值。跨关卡与失球后清空定时效果，保证规则可预测。

## 10. 计分、生命与结算

### 10.1 计分

砖块被彻底销毁时加分：普通砖和道具砖各 100 分；坚固砖总计 200 分（可在每次命中时各加 100 分）。道具被成功接取时另加 50 分。HUD 必须在同一更新帧内反映最新分数。

### 10.2 失球

当 `balls` 为空时：

1. `lives` 减一。
2. 若 `lives > 0`，进入 `READY` 并执行准备发球。
3. 否则进入 `GAME_OVER`，显示最终分数与重新开始按钮。

### 10.3 清关

当所有可破坏砖块被销毁时：

1. 立即停止当前小球和道具更新。
2. 增加 `lives × 500` 的清关奖励。
3. 进入 `LEVEL_CLEAR`，展示本关结果。
4. 若仍有下一关，等待玩家确认后加载；否则进入 `VICTORY`。

## 11. 渲染与 UI

### 11.1 Canvas 绘制层级

每帧按以下顺序清屏并重绘：

1. 背景与边框。
2. 砖块（按类型、耐久选取颜色）。
3. 掉落道具与其图标/文本缩写。
4. 挡板。
5. 小球与轻量尾迹、碰撞粒子（如实现）。
6. 状态提示（如“按空格发球”）。

### 11.2 DOM UI

分数、生命和关卡信息放在 Canvas 外的 HUD 中，避免每帧在 Canvas 绘制大量文字。开始、暂停、关卡结算、结束和通关均使用同一个遮罩容器，根据状态替换标题、说明和按钮文字。

按钮应支持鼠标点击；关键动作同时支持键盘，颜色不作为唯一状态区分方式。

## 12. 错误处理与资源释放

- 关卡索引无效时回退到开始界面并记录开发期错误。
- 不认识的砖块或道具类型应跳过生成并记录警告，不能使整局崩溃。
- 重新开始、换关、失球时移除旧数组中的球、掉落物和过期效果，避免引用残留。
- 页面卸载或游戏实例销毁时注销键盘、焦点和按钮事件监听器。
- 音频与本地存储均视为可选能力；调用失败时静默降级到无音频/无存档。
