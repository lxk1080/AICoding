# 《打砖块》音乐设计文档

## 1. 目标

为《打砖块》增加轻量的街机风格背景音乐和关键交互音效，以增强游戏节奏与反馈。音频功能不依赖外部音频文件，使用浏览器 Web Audio API 以程序化方式生成，避免额外资源下载与版权问题。

## 2. 音频组成

| 类型 | 内容 | 作用 |
| --- | --- | --- |
| 背景音乐 | 循环播放的 8-bit/街机风格旋律 | 建立游戏氛围，保持单局节奏。 |
| 墙壁碰撞音效 | 短促、音高较低的提示音 | 区分普通边界反弹。 |
| 挡板碰撞音效 | 较明亮的提示音 | 强化成功接球的反馈。 |
| 砖块碰撞音效 | 按砖块类型区分音高或音色 | 强化击中与坚固砖受损反馈。 |
| 道具音效 | 上行短音阶 | 提示成功接到道具。 |
| 失球音效 | 下行短音阶 | 明确提示损失生命。 |
| 清关/通关音效 | 较长的上行和弦或短旋律 | 提供阶段完成的奖励感。 |

首版的背景音乐和音效均应保持低音量，避免遮挡玩家对游戏操作的注意力。

## 3. 播放状态与默认行为

### 3.1 默认设置

- 默认音频状态：**未静音**。
- 页面初始化时创建音频管理器和背景音乐播放计划，使页面一打开就具备播放音乐的能力。
- 若本地保存过音频偏好，优先使用保存的静音状态。
- 静音时：停止或挂起背景音乐，不播放任何游戏音效。
- 非静音时：背景音乐应保持可播放状态；开始游戏后持续循环，直至用户静音、关闭页面或游戏实例销毁。

### 3.2 浏览器自动播放限制

现代浏览器通常不允许网页在没有用户手势时直接播放带声音的音频。因此“打开界面就有能力播放”的实现规则为：

1. 页面加载后立即创建或预创建 `AudioContext` 与音乐序列；此时不因加载失败影响游戏。
2. 若浏览器允许自动播放且当前未静音，立即开始背景音乐。
3. 若浏览器阻止自动播放，保留待播放状态。
4. 用户第一次有效交互（点击“开始游戏”、按 Enter、Space、Escape、A/D 或方向键）时：
   - 若未静音，恢复 `AudioContext` 并立即开始背景音乐；
   - 若已静音，不恢复播放。
5. 该限制属于浏览器安全策略，不应显示为游戏错误或中断游戏流程。

这样既满足页面初始即具备播放能力的目标，也兼容浏览器的自动播放规则。

## 4. 背景音乐播放时机

| 游戏状态/事件 | 未静音时的行为 |
| --- | --- |
| 页面初始化 | 创建音频能力；浏览器允许时立即播放，否则等待首次交互。 |
| 开始界面 | 背景音乐可播放，使用较低音量。 |
| 点击开始或 Enter 发球 | 确保背景音乐已启动；不重复创建多个循环。 |
| `READY` / `PLAYING` | 正常循环播放背景音乐。 |
| `PAUSED` | 暂停或挂起背景音乐；恢复游戏时从当前音乐位置继续。 |
| 关卡结算 | 先播放清关提示音；背景音乐可短暂降低音量，进入下一关后恢复。 |
| 游戏结束 / 最终通关 | 停止背景循环，播放对应结算音效。 |
| 重新开始 | 重新启动背景音乐循环，不产生叠加播放。 |
| 切换静音 | 立即停止/挂起全部声音；取消静音后按当前游戏状态恢复背景音乐。 |

## 5. 静音控制与持久化

- 在 HUD 或游戏卡片底部提供一个可访问的“音乐/静音”切换按钮，包含文本或 `aria-label`，不只依赖图标或颜色。
- 按钮状态应明确显示“音乐开”或“已静音”。
- 音频偏好以 `localStorage` 保存，例如键名 `brick-breaker-muted`。
- 页面加载时读取该值：`true` 表示静音，其他情况按默认未静音处理。
- `localStorage` 不可用时，使用内存中的默认值；不得阻塞游戏。

## 6. 音量与混音规则

| 音频类别 | 建议相对音量 | 备注 |
| --- | ---: | --- |
| 背景音乐 | 0.10～0.16 | 长时间循环，必须克制。 |
| 墙壁/挡板 | 0.12～0.20 | 短音，避免频繁反弹造成刺耳。 |
| 砖块 | 0.10～0.18 | 可按砖块类型做细微变化。 |
| 道具/结算 | 0.18～0.28 | 重要事件，可略高于普通碰撞。 |

同一时刻若发生多次砖块碰撞，应限制并发音效数量或做极短的节流，避免多球状态下产生爆音。

## 7. 程序化音乐设计

### 7.1 背景音乐

- 风格：明亮、循环感强的 8-bit 街机音乐。
- 节拍：建议 4/4，约 120～135 BPM。
- 结构：8 小节主循环；主旋律、低音和简易节奏轨分层生成。
- 音色：优先使用方波、三角波和低音量噪声，避免复杂采样。
- 循环：使用基于 `AudioContext.currentTime` 的预排程方式，确保循环衔接稳定，不能依赖 `setInterval` 的不精确计时。

### 7.2 音效映射

| 事件 | 建议音色/音高变化 |
| --- | --- |
| 墙壁反弹 | 短三角波，低至中音。 |
| 挡板反弹 | 短方波，中音上行。 |
| 普通砖 | 短方波，中音。 |
| 坚固砖 | 更低沉的双击感；第一次受击与击碎使用不同音高。 |
| 金属砖 | 短促、高频、带金属感的音色。 |
| 道具砖 | 明亮的上行音。 |
| 接取道具 | 快速上行三音。 |
| 失球 | 下行三音。 |
| 清关/通关 | 上行和弦或短胜利旋律。 |

## 8. 技术接口建议

新增独立的 `AudioManager` 模块，避免把音频生成和游戏物理逻辑混在一起。

| 接口 | 职责 |
| --- | --- |
| `initialize()` | 读取静音偏好，创建或准备音频上下文与音量节点。 |
| `ensureStarted()` | 在允许播放时恢复音频上下文并开始背景音乐；多次调用应安全。 |
| `playSfx(name)` | 按事件名称播放短音效，并应用静音与并发限制。 |
| `pauseMusic()` / `resumeMusic()` | 响应游戏暂停与恢复。 |
| `setMuted(boolean)` | 立即切换静音状态、保存偏好并更新播放状态。 |
| `stopMusic()` | 在游戏结束、通关或销毁时停止背景音乐。 |
| `destroy()` | 关闭音频资源并清理计划任务。 |

游戏状态机与音频接口的对应关系：

```text
页面加载 → AudioManager.initialize()
首次用户交互且未静音 → AudioManager.ensureStarted()
球/砖块/道具事件 → AudioManager.playSfx(...)
PAUSED → AudioManager.pauseMusic()
恢复游戏 → AudioManager.resumeMusic()
GAME_OVER / VICTORY → AudioManager.stopMusic() + 结算音效
```

## 9. 验收标准

- 页面加载后已完成音频初始化或待播放准备，不影响未支持音频的浏览器打开游戏。
- 未静音且浏览器允许时，背景音乐会在打开界面后播放。
- 浏览器阻止自动播放时，首次用户交互后会自动开始背景音乐。
- 静音状态下不播放背景音乐和音效；取消静音后能按当前游戏状态恢复。
- 暂停、恢复、失球、清关、通关和重新开始的音乐行为符合第 4 部分规则。
- 背景音乐不会因多次点击、反复暂停或换关而重复叠加。
- 道具、多球和高频碰撞时不存在明显爆音或严重性能下降。
